# Checklist - 核心检测模块重构与新增

## Phase 1: 基础设施验证

### 基础框架验证

- [ ] **基础类完整性**
  - `DetectionModule` 接口定义了所有必需方法（getName, check, getProbability）
  - `DetectionResult` 正确封装概率值和证据
  - `Evidence` 能够序列化并存储到数据库
  - 模块管理器支持动态注册和卸载

- [ ] **物理引擎工具类**
  - `Vector3D` 实现了所有向量运算（加、减、乘、除、点乘、叉乘、长度、归一化）
  - `PhysicsConstants` 包含所有Minecraft物理常量（摩擦力、重力、跳跃高度等）
  - `EntitySnapshot` 能记录并恢复实体完整状态
  - `MovementInput` 能记录所有移动按键状态

### 贝叶斯网络验证

- [ ] **贝叶斯网络核心功能**
  - 节点能存储条件概率分布
  - 网络能进行前向推理计算
  - 概率表能根据反馈动态更新
  - 支持多父节点的复杂依赖关系

## 端到端测试场景

### 场景1: 正常玩家不误报
- **WHEN** 正常玩家进行各种合法操作
- **THEN** 所有检测模块不触发或概率极低
- **AND** 玩家不受到任何干扰

### 场景2: 已知作弊器检测
- **WHEN** 玩家使用已知的作弊软件
- **THEN** 相关检测模块触发
- **AND** 概率值达到阈值
- **AND** 自动记录证据

### 场景3: 高级作弊器检测
- **WHEN** 玩家使用带有"人类化"功能的作弊器
- **THEN** 多维度分析能识别
- **AND** 综合概率超过阈值
- **AND** 小号/团伙关联检测能发现

### 场景4: 网络异常处理
- **WHEN** 网络出现高延迟或不稳定
- **THEN** 系统能正确处理
- **AND** 不产生大量误报
- **AND** 恢复正常后立即正常工作

### 场景5: 自适应学习验证
- **WHEN** 管理员判罚多个案例
- **THEN** 系统能学习正确的判断
- **AND** 误报率逐步降低
- **AND** 检测准确性逐步提高
